# omnivoice_uk_samples_doctor

Веб-сервіс для перевірки та виправлення голосових семплів (референсів) для клонування голосу в OmniVoice
українською мовою.

## Для якого стеку

Пороги й кроки виправлення підібрано експериментально під такий конвеєр синтезу:

- **[OmniVoice](https://github.com/k2-fsa/OmniVoice)** (k2-fsa) — zero-shot TTS із клонуванням голосу;
- **[dkaraush/omnivoice-lora-uk](https://huggingface.co/dkaraush/omnivoice-lora-uk)** — LoRA-дотренування
  OmniVoice для української;
- **[accentuk](https://pypi.org/project/accentuk/)** — розстановка наголосів і нормалізація тексту
  (числа, дати, одиниці) перед синтезом.

Для інших моделей висновки можуть не збігатися.

Голос у цьому стеку — це пара файлів: аудіо (`.mp3`) і `.info` (JSON) з полями `name`, `ref_text`
(точний текст семпла), `cfg_strength`, `speed`, `stressed_ref_text`.

## Що з'ясовано про семпли

| Властивість семпла | Вплив на синтез |
|---|---|
| Транскрипт не збігається з аудіо | головна причина «ковтання» фраз, «відсебеньок» і шматків семпла на початку синтезу |
| Транскрипт не задано | модель розпізнає сама; це краще, ніж неточний транскрипт |
| Шум, луна | переходять у синтез і знижують схожість голосу |
| Менше ~6 с мовлення | схожість голосу помітно падає (3 с — сильно) |
| Повільний або швидкий темп | синтез повторює темп; дуже швидкий семпл дає ковтання слів |
| Запис обірвано відразу після слова | зайвий звук на початку синтезу |
| mp3 32 кбіт/с, довгі паузи, тиша на краях | майже не шкодять |

## Що робить сервіс

- зберігає список семплів (завантаження файлів; аудіо + `.info` з тією ж назвою);
- **розпізнає** мовлення (Whisper) і пропонує заповнити `ref_text`, якщо його немає;
- **аналізує**: тривалість мовлення, тиша на краях, паузи, гучність, перевантаження, шум (SNR), смуга
  частот, темп (у термінах оцінювача тривалості OmniVoice), розбіжність транскрипту з розпізнаванням;
- **виправляє**: обрізає задовгий семпл до 6–12 с по межі речення, прибирає шум
  ([Sidon](https://huggingface.co/sarulab-speech/sidon-v0.1); за замовчуванням лише для шумних записів,
  бо він трохи змінює тембр), підрізає краї й лишає 0,2 с тиші в кінці, обмежує паузи, вирівнює гучність;
- **віддає** результат як `.mp3` + `.info` (ZIP); якщо встановлено accentuk, `stressed_ref_text`
  перераховується.

Транскрипт користувача не замінюється розпізнаним, доки той не відрізняється докорінно (WER > 0,3):
Whisper сам помиляється на сленгу та іменах.
Фрази, які Whisper вигадує на тихому хвості («Субтитрувальниця Оля Шор», «Дякую за перегляд»), прибираються.
Якщо Whisper зациклився на протяжному звуці («Міссссс…»), його текст не порівнюється з транскриптом,
а обрізання по словах вимикається.

## Ресурси

- Моделі завантажуються лише тоді, коли потрібні, і вивантажуються після простою (за замовчуванням 300 с).
- Перед завантаженням моделі сервіс перевіряє вільну пам'ять; якщо її бракує, спершу вивантажує інші
  моделі, а потім пропускає крок (наприклад, шумоочищення) і пише про це в результаті.
- Завдання виконуються по одному.
- Перемикач CPU / GPU і вибір моделі розпізнавання — в налаштуваннях інтерфейсу. На CPU зручніше
  `whisper-large-v3-turbo` або `whisper-small`.
- Пам'ять: Whisper large-v3 ~3,6 ГБ (GPU, fp16), Sidon ~2,2 ГБ. Моделі завантажуються з Hugging Face
  при першому використанні в `data/models`.

## Запуск

Потрібні Python 3.10+ і, для mp3 без libsndfile 1.1+, `ffmpeg` у PATH.

Linux:

```bash
./run.sh
```

Windows:

```bat
run.bat
```

Перший запуск створює `.venv` і ставить залежності. Збірку PyTorch вибирає змінна `TORCH_INDEX`
(за замовчуванням CUDA 12.8, підходить для RTX 50xx):

```bash
TORCH_INDEX=https://download.pytorch.org/whl/cpu ./run.sh          # лише CPU
TORCH_INDEX=https://download.pytorch.org/whl/cu130 ./run.sh        # CUDA 13 (напр. DGX Spark / GB10)
```

Після запуску відкрийте в браузері **http://127.0.0.1:8780**.

Параметри (або змінні середовища):

| Параметр | Змінна | За замовчуванням | |
|---|---|---|---|
| `--host` | `DOCTOR_HOST` | `127.0.0.1` | `0.0.0.0` — доступ із мережі |
| `--port` | `DOCTOR_PORT` | `8780` | |
| `--data` | `DOCTOR_DATA` | `data` | семпли, налаштування, кеш моделей |
| `--token` | `DOCTOR_TOKEN` | — | токен доступу до API |

Доступ із локальної мережі:

```bash
./run.sh --host 0.0.0.0 --token "довгий-випадковий-рядок"
```

Інтерфейс попросить токен один раз і запам'ятає його в браузері.

Необов'язково, для `stressed_ref_text` у вихідному `.info`:

```bash
.venv/bin/pip install accentuk && .venv/bin/accentuk download --light
```

## Безпека

- Файли семплів зберігаються під ідентифікаторами, які генерує сервер; назва файлу від користувача
  ніколи не стає шляхом. Віддаються лише файли семплів зі сховища.
- Приймаються лише аудіофайли з білого списку (до 64 МБ), які вдалося декодувати.
- Без `--token` сервіс слухає лише `127.0.0.1`; відкривати його в мережу без токена не варто.
  HTTPS сервіс не робить — для доступу ззовні ставте перед ним зворотний проксі.

```
run.py              точка входу

doctor/analysis.py  вимірювання семпла
doctor/repair.py    виправлення
doctor/sidon.py     шумоочищення Sidon
doctor/models.py    завантаження / вивантаження моделей, контроль пам'яті
doctor/jobs.py      черга завдань
doctor/store.py     сховище семплів
doctor/web.py       HTTP API
doctor/static/      інтерфейс
```
